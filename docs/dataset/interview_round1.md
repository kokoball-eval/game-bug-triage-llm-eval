# v1.3 평가셋 설계 인터뷰 — 1차 (분류 체계)

> 2026-10-01
> 회사명·작품명 등 식별 정보는 포함하지 않습니다.

## 전제

- 가상 게임 "Aether Raid"는 **모바일 + PC 크로스플랫폼 RPG**로 둔다.
- v1.0 평가셋 10문항(`data/questions.json`)은 README 수치의 출처이므로 그대로 보존하고, v1.3 평가셋은 새 파일로 만든다.
- PC·모바일은 구분하지 않고 통합해서 답변했다.

## Q1. 리포트는 어떤 경로로 들어왔나?

**답변 요지** — 이슈의 9할 이상이 JIRA·Redmine 같은 BTS를 통해 들어왔다. 등록 경로는 다음 네 가지다.

- 개발 QA가 테스트 중 발견한 결함과 개선 제안을 BTS에 등록하고 담당자와 협업한다.
- 개발 담당자(기획·프로그래밍·아트 등)가 결함이나 개선점을 발견해 직접 등록한다.
- 개발 QA가 완료되어 패키징된 빌드를 퍼블리셔에 전달하면, 퍼블리셔 서비스 QA가 테스트 중 발견한 결함과 개선 제안을 BTS에 등록해 개발사로 이관한다. 개발사는 담당자에게 전달해 수정하고, 다음 패키징 빌드에 반영해 전달한다.
- 외부 커뮤니티와 게임 공식 홈페이지 등에 올라온 유저 제보를 분석하고 재현 여부를 확인해 BTS에 등록한다.

## Q2. 리포트 품질의 대략적 비율은?

**답변 요지** — BTS 전체 기준으로 다음과 같다.

| 제보 품질 | 비율 |
| :--- | ---: |
| 재현 절차까지 명확한 제보 | 60% |
| 한두 줄짜리 단문 | 5% |
| 감정적 불만 | 15% |
| 여러 이슈가 섞인 제보 | 3% |
| 중복 제보 | 2% |
| 버그가 아닌 문의·건의 | 10% |

등록 경로별로는 신규 콘텐츠 검증 중 내부에서 발급된 이슈가 약 45%, 퍼블리셔 서비스 QA가 등록한 이슈가 약 50%, 유저 제보가 약 5%다. 콘텐츠 기준으로는 기존 콘텐츠에서 발생한 문제가 약 20%, 신규 콘텐츠가 약 80%다.

## Q3. 자주 들어온 결함 유형은?

**답변 요지** — 다음 18개 유형이 자주 들어왔다.

1) 크래시 및 프리징 2) 네트워크 끊김 및 동기화 오류 3) 로그인 및 계정 연동 오류 4) 퀘스트 진행 불가 5) 충돌(콜리전) 및 물리엔진 오류 6) 사운드 출력 오류 7) 밸런스 오류 8) 그래픽 및 애니메이션 렌더링 오류 9) UI 표시 및 조작 오류 10) 미번역 및 더미 텍스트 노출 11) 어뷰징 및 익스플로잇 취약점 12) 프레임 드랍 및 발열 13) 기기 해상도 호환성 14) 네트워크 전환 대응 미비 15) 인터럽트(Interrupt) 대응 실패 16) 외부 모듈(SDK) 충돌 17) 메모리 변조 방어 실패 18) 매크로 및 봇(Bot) 방어 취약점

## Q4. 심각도 체계와 등급별 기준은?

**답변 요지** — 실무에서는 심각도를 쓰지 않고, 개발사의 **대응 우선순위**(Critical / Major / Minor / Trivial)로 나눠 관리하고 그에 맞춰 대응했다. 등급별 기준은 다음과 같다.

**1) Critical** — 게임의 핵심 진행을 완전히 차단하거나, 유저 데이터 및 회사 매출(비즈니스)에 치명적인 타격을 주는 최고 수준의 결함입니다. 우회할 수 있는 방법(Workaround)이 없습니다. 발견 즉시 보고되며, 출시 전이라면 빌드를 멈추고서라도 고쳐야 합니다. 라이브 서비스 중이라면 즉각적인 임시 점검(Hotfix)을 진행해야 합니다.
- 게임 실행 불가, 로딩 중 100% 확률로 앱 강제 종료(Crash).
- 결제를 했는데 유료 재화가 들어오지 않거나, 반대로 돈이 빠져나가지 않고 재화만 무한히 얻어지는 결제 버그.
- 유저의 세이브 데이터가 날아가거나 계정 로그인이 불가능한 현상.
- 메인 퀘스트 NPC가 스폰되지 않아 모든 유저의 게임 진행이 멈추는 현상(Blocker).

**2) Major** — 핵심 기능이나 플레이 경험에 큰 지장을 주지만, 게임 구동 자체가 불가능한 것은 아니거나 특정 조건(우회 방법)을 통해 피할 수 있는 결함입니다. 다음 정기 업데이트나 마일스톤 마감 전까지 반드시 수정해야 하는 목표가 됩니다. 이를 방치하고 출시할 경우 유저들의 대규모 불만(CS)이 발생합니다.
- 특정 캐릭터의 핵심 스킬 데미지가 아예 들어가지 않는 현상.
- 일부 구형 기기에서 화면 프레임이 심하게 떨어져 정상적인 전투 조작이 힘든 현상.
- 필수가 아닌 서브 퀘스트의 완료가 불가능한 현상.
- 상점 UI가 심하게 깨져 아이템 구매 시 텍스트나 가격을 알아보기 힘든 현상.

**3) Minor** — 게임의 핵심 코어 루프나 진행에는 문제가 없지만, 유저 경험(UX)을 깎아먹거나 부가 기능이 기획 의도와 다르게 작동하는 결함입니다. 일정이나 리소스에 여유가 있을 때 수정합니다. 출시 일정이 촉박할 경우, '알려진 문제(Known Issue)'로 남겨두고 출시 후 패치로 미루는 경우가 많습니다.
- 아이템 설명 텍스트가 너무 길어 UI 상자 바깥으로 삐져나가는 현상(Overflow).
- 특정 몬스터를 타격할 때 효과음(SFX)이 약간 늦게 출력되는 현상.
- 조작에는 문제가 없으나, 캐릭터가 특정 벽에 비비면 팔 부위가 벽을 파고드는 현상(가벼운 클리핑 버그).
- 업적 보상 아이콘이 다른 이미지로 잘못 출력되는 현상.

**4) Trivial** — 게임 플레이에 전혀 지장을 주지 않으며, 주의 깊게 보지 않으면 유저 대부분이 눈치채지 못할 수준의 매우 미관상, 지엽적인 결함입니다. 우선순위가 가장 낮습니다. 개발 리소스 대비 수정 효율이 떨어지면 서비스 종료 때까지 고치지 않고 안고 가는(Won't fix) 경우도 허다합니다.
- 스토리 대사나 아이템 설명의 단순 오타 및 띄어쓰기 오류.
- UI 버튼의 위치가 1~2픽셀(px) 정도 미세하게 어긋나 있는 현상.
- 극도로 특이한 행동(예: 점프를 하면서 동시에 인벤토리를 열고 특정 아이템을 버림)을 할 때만 발생하는 중요하지 않은 시각적 오류.
- 구석에 배치된 오브젝트(예: 배경의 작은 돌멩이)의 그림자가 렌더링되지 않는 현상.

## Q5. 판정이 애매하거나 사람마다 갈리던 케이스는?

**답변 요지** — 다음 다섯 가지 유형에서 부서마다 판정이 갈렸다.

1. **기괴한 그래픽 깨짐 (Visual Glitch)** — 컷신에서 캐릭터의 안면 텍스처가 날아가 눈알과 치아만 둥둥 떠다니는 경우입니다. 게임이 멈추지도, 튕기지도 않으므로 기술적 기준으로는 Minor입니다. 하지만 유저들이 이를 캡처해 커뮤니티에 올리면 '조롱거리'가 되어 마케팅에 심각한 타격을 주므로 사업부에서는 Critical로 취급해 당장 고치라고 요구합니다.
2. **민감한 텍스트 오타** — 단순 오타는 Trivial이지만, 그 오타가 특정 국가의 정치적·역사적 분쟁 지역 명칭을 잘못 표기했거나, 우연히 심한 욕설이 되어 필터링을 우회한 경우입니다.
3. **구형/특정 기기에서의 확정 크래시** — 출시된 지 7년이 넘은 특정 저사양 스마트폰 모델에서 보스전에 진입할 때 무조건 게임이 강제 종료(Crash)됩니다. 크래시 자체는 Critical 결함입니다. 하지만 해당 기기를 사용하는 유저가 전체의 0.1%도 되지 않고 수정하려면 코어 엔진을 건드려야 하는 경우, 개발팀은 리소스 대비 효율을 이유로 Minor 또는 '수정 안 함(Won't fix)'으로 판정하려 하고, QA는 '확정 크래시를 수정하지 않고 출시할 수 없다'는 입장으로 대립합니다.
4. **지형지물을 이용한 꼼수 사냥 (안전지대)** — 몬스터의 AI가 인식하지 못하거나 공격이 닿지 않는 특정 좁은 바위 위에 올라가서, 유저가 원거리 공격만으로 보스를 일방적으로 잡는 상황입니다.
   - 기획팀: "의도하지 않은 밸런스 붕괴이므로 Major 버그다."
   - QA팀: "유저가 높은 숙련도로 특정 위치를 찾아낸 것이며 시스템 오류(충돌 무시 등)가 발생한 것은 아니므로 Minor 또는 Not a Bug(버그 아님)이다."
   - 실제로 이를 버그로 간주해 수정했다가 "개발사가 공략의 재미를 빼앗고 과금을 유도한다"는 유저 반발이 크게 일어나는 경우도 잦습니다.
5. **기획서대로 작동하지만 UX가 최악인 경우 (반복 조작 강요)** — 인벤토리에 쌓인 하급 장비 100개를 상점에 팔아야 하는데, '일괄 판매' 버튼이 없어서 유저가 아이템 클릭 → 판매 버튼 클릭 → 확인 팝업 클릭 과정을 100번 반복해야 합니다.
   - QA팀: "이대로 출시하면 유저가 피로감으로 이탈할 가능성이 높으므로 Major급 결함이다."
   - 개발팀: "기능 오류가 아니며 기획서대로 구현했으므로 결함이 아니다(Not a Bug). 개선 사항(Suggestion)으로 따로 분류해야 한다."
