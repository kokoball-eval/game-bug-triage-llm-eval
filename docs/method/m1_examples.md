# M1 판정 예시 4개 (v1.4 방법 비교)

> 검토자 승인 2026-10-04. 측정 전 확정본이며 결과를 본 뒤 바꾸지 않습니다. 계획: [method_comparison_v14_plan.md](../../report/method_comparison_v14_plan.md)

평가셋 88건과 겹치지 않게 새로 쓴 가상 리포트입니다. 고유명사(펫, 낚시, 우편함 아이콘, 주간 보상)는 평가셋에 없는 것으로 골랐습니다.
모델에는 아래 [입력]과 [출력]이 그대로 들어갑니다.

---

## E1 — 운영 문의 (등급: 해당 없음)

**[입력]**
```text
[입력 종류] (A) 커뮤니티 제보 원문
[게시판] 자유게시판
[게시 일시] 2026-08-03 20:14
[제목] 펫 이름 변경권 어디서 사요?
[본문]
펫 이름 바꾸고 싶은데 상점에 아무리 찾아도 없네요. 이벤트로만 주는 건가요?
```

**[출력]**
```text
[요약]: 펫 이름 변경권 구매처 문의
[분류]: 문의·건의
[모듈]: 해당 없음
[우선순위]: 해당 없음
[재현 정보]: 부족
[발생 빈도]: 해당 없음
[처리]: CS 응대
[누락 정보 및 권장 조치]: 결함 정보 없음. 운영/CS가 펫 이름 변경권 획득 경로를 안내
```
근거: C-3(운영 문의), H-6, 우선순위 정의(결함이 아닌 글은 해당 없음)

---

## E2 — 정보 부족 단문 (등급: 판단보류)

**[입력]**
```text
[입력 종류] (A) 커뮤니티 제보 원문
[게시판] 자유게시판
[게시 일시] 2026-08-05 22:41
[제목] 낚시하면 멈춤
[본문]
낚시만 하면 화면 멈춰요
```

**[출력]**
```text
[요약]: 낚시 중 화면 멈춤 제보
[분류]: 결함
[모듈]: 클라이언트 안정성
[우선순위]: 판단보류
[재현 정보]: 부족
[발생 빈도]: 미기재
[처리]: 정보 요청 후 보류
[누락 정보 및 권장 조치]: 기기/플랫폼, 낚시 장소, 멈춘 뒤 복구되는지 여부 요청. 멈춤이 계속되면 진행 불가일 수 있으므로 개발 QA 재현 확인 병행
```
근거: R-3(기기·장소 없음), H-3a(멈춤은 Critical 가능성 → 정보 요청 + 재현 확인 병행), F-1('~하면 ~됨' 조건문 → 미기재)

---

## E3 — 미관 결함 (등급: Trivial)

**[입력]**
```text
[입력 종류] (B) QA 작성 BTS 이슈
[작성자] 내부 QA
[제목] [UI] 우편함 닫기 버튼 아이콘이 2px 왼쪽으로 어긋남
[본문]
[테스트 환경]
PC / 빌드 2.3.0.1544 (QA 빌드)

[재현율]
10/10 (100%)

[이슈 설명]
우편함 창 오른쪽 위 닫기(X) 버튼의 아이콘이 버튼 영역 중앙에서 왼쪽으로 2px 치우쳐 표시됨. 버튼 입력은 정상.

[기대 결과]
아이콘이 버튼 영역 중앙에 표시된다.

[실제 결과]
아이콘이 왼쪽으로 2px 치우침. 클릭·터치 영역은 정상.

[참고 문서]
UI 가이드 v2
```

**[출력]**
```text
[요약]: 우편함 닫기 버튼 아이콘이 2px 어긋나 표시됨(입력 정상)
[분류]: 결함
[모듈]: UI·텍스트
[우선순위]: Trivial
[재현 정보]: 충분
[발생 빈도]: 항상
[처리]: 개발 배정
[누락 정보 및 권장 조치]: 없음. 다른 창의 닫기 버튼도 같은 어긋남이 있는지 확인 권장
```
근거: §4.1 Trivial(1~2픽셀 어긋남, 플레이 지장 없음), R-1, F-1(10/10 → 항상), H-2b

---

## E4 — 눈에 띄지 않는 Critical (반복 획득 악용)

**[입력]**
```text
[입력 종류] (A) 커뮤니티 제보 원문
[게시판] 공식 홈페이지 > 버그 제보
[게시 일시] 2026-08-07 11:20
[제목] 주간 보상이 캐릭터마다 다시 받아져요
[본문]
PC로 합니다. 주간 퀘스트 보상(계정당 1회라고 써 있음)을 받은 뒤 캐릭터 선택 화면에서 다른 캐릭터로 바꾸면 보상 받기 버튼이 다시 켜집니다.
제 캐릭터 3개로 해봤는데 세 번 다 다시 받아졌고 보상은 계정 공용 창고로 들어갑니다. 이거 막아야 할 것 같아서 제보합니다.
```

**[출력]**
```text
[요약]: 계정당 1회인 주간 퀘스트 보상을 캐릭터를 바꿔 가며 반복 수령 가능
[분류]: 결함
[모듈]: 결제·재화 / 보안·어뷰징
[우선순위]: Critical
[재현 정보]: 충분
[발생 빈도]: 항상
[처리]: 긴급 사인 요청
[누락 정보 및 권장 조치]: 보상 지급 로그로 반복 수령 계정 확인, 계정 단위 수령 제한 로직 점검
```
근거: §4.1 Critical(보상을 반복해서 얻는 악용 — 장애가 눈에 띄지 않아도 피해가 쌓임), R-2, F-1('세 번 다' → 항상), H-1

---

## 설계 메모
- 게시 일시는 2026-08로 두어 평가셋(2026-09·10)의 업데이트 공지와 섞이지 않게 했습니다. 예시에는 업데이트 공지·기존 이슈 블록을 넣지 않아 입력 길이를 줄였습니다.
- 네 예시의 정답이 서로 다른 등급(해당 없음·판단보류·Trivial·Critical)과 다른 처리(CS 응대·정보 요청 후 보류·개발 배정·긴급 사인 요청)를 갖도록 골랐습니다. 한쪽으로 쏠리면 모델이 그 답을 따라 하는 경향이 생기기 때문입니다.
- Major·Minor 예시는 넣지 않았습니다. 현재 모델은 이미 Major·Minor 쪽으로 치우쳐 있어(오답의 대부분이 Major·Minor로 답한 경우), 이 두 등급의 예시를 더하면 치우침이 강해질 수 있습니다.
