# v1.5 라벨 일치율 측정 계획 (사전 등록)

> **상태: 판정 수집 전 확정 (2026-10-08).** 이 문서와 [`label_agreement_v15.toml`](../label_agreement_v15.toml)은 채점자에게 판정 시트를 보내기 전에 커밋한다. 받은 판정을 본 뒤에는 기준과 계산 방법을 바꾸지 않는다.
> 본문의 [ML]·[PE] 표기는 KANT AI 부트캠프 Private LLM 트랙 과정 기록(TIL) 링크다.

## 요약

- **질문** — 같은 판정 기준서로 다른 QA가 판정해도 지금의 정답 라벨과 같은 판정이 나오는가?
- **방법** — 프로젝트에 참여하지 않은 게임 QA 2명(시니어급·주니어급)이 정답 라벨을 보지 않고 개발용 63건의 6칸을 각자 판정한다. 기존 라벨과 얼마나 같은지, 두 사람끼리 얼마나 같은지를 잰다.
- **쓰임** — 기준을 넘은 칸은 지금까지의 정답률을 그대로 인정한다. 못 넘은 칸은 불일치 문항을 모델 응답을 보지 않은 채 검토해 기준서나 라벨을 고치고, 판단이 원래 갈리는 문항은 v1.5 라우팅에서 사람 검토로 보낼 근거로 쓴다.

## 1. 왜 재는가

v1.0~v1.4의 정답률, Critical 누락, 회귀 게이트 판정은 모두 **정답 라벨이 맞다는 전제** 위에 있다. 그런데 라벨은 검토자 한 명이 기준서를 만들고 그 기준서로 확정했다. 기준서가 검토자의 머릿속 기준과 같기 때문에, 기준서가 모호한 곳이 있어도 검토자 혼자서는 드러나지 않는다.

v1.5의 목표인 라우팅(확신할 수 있는 건은 자동 등록, 확신할 수 없는 건은 사람 검토)은 "자동 처리분 정확도"를 재야 한다. 라벨이 흔들리면 그 정확도도 흔들린다. 그래서 라우팅보다 먼저 라벨을 잰다.

QA 실무로 보면, 심각도 기준표를 새로 만든 뒤 다른 QA들에게 같은 이슈를 판정하게 해 판정이 맞는지 맞춰 보는 **교차 판정(캘리브레이션)**과 같다. 사람마다 갈리는 항목이 나오면 기준표의 문구가 모호하거나 원래 부서마다 판단이 갈리는 영역이다.

## 2. 무엇을 재는가

| 항목 | 내용 | 이유 |
| :--- | :--- | :--- |
| 채점자 | 채점자 1(시니어급 게임 QA), 채점자 2(주니어급 게임 QA). 프로젝트에 참여하지 않음 | 기준서를 만든 사람과 다른 사람이어야 기준서의 모호함이 드러난다. 경력이 다른 두 사람이면 경험에 따라 판정이 갈리는 곳도 보인다 |
| 문항 | 개발용 63건 (Critical 측정 20건, 결함 폐기 측정 12건, 사람 확인 측정 11건 포함) | 최종 평가용 25건은 봉인 원칙에 따라 쓰지 않는다 |
| 판정 칸 | 분류, 모듈, 우선순위, 재현 정보, 발생 빈도, 처리 | 모델 정답률을 재는 6칸과 같다 |
| 채점자가 보는 것 | 리포트 원문(모델 입력과 같은 내용)과 [채점자용 안내서](../docs/label_agreement/rater_guide.md) | 모델과 같은 조건에서 판정하게 한다 |
| 보지 않는 것 | 정답 라벨, 판정 근거, 원래 문항 번호, 문항 세트·위험 표시, 모델 응답, 다른 채점자의 판정 | 정답이나 다른 사람의 판정을 보면 따라가게 되어 독립 판정이 아니다 |

**블라인드 처리** — 원래 문항 번호(A01·B01·S01)는 트랙과 "판정이 까다로운 집중 세트"를 드러내므로, 고정 seed로 섞어 Q01~Q63으로 다시 번호를 붙였다. 대응표는 저장소([`data/label_agreement/blind_map_v15.json`](../data/label_agreement/blind_map_v15.json))에만 둔다. 판정 시트는 [`tools/label_agreement/build_sheets.py`](../tools/label_agreement/build_sheets.py)가 평가셋에서 만들며, 정답·근거가 들어가지 않는지 테스트로 확인한다.

**안내서** — 채점자용 안내서는 판정 기준서 v1.4의 규칙을 그대로 옮기고, 근거 출처와 평가 문항 번호만 뺐다(기준서의 경계 규칙 표에는 문항 번호가 적혀 있어 그대로 보내면 정답이 드러난다). 안내서에 평가 문항 번호가 없는지도 테스트로 확인한다. 예시 2건은 평가셋과 겹치지 않는 가상 리포트다(v1.4 판정 예시 E2·E3).

## 3. 지표

| 지표 | 계산 | 쉽게 말하면 |
| :--- | :--- | :--- |
| **허용 답 일치율** | 채점자의 답이 정답 라벨의 허용 답 안에 있는 문항 비율. 모델 채점과 같은 함수(`score.field_correct`)를 쓴다 | 모델을 채점하는 잣대로 사람을 채점했을 때 몇 %를 맞히는가 |
| **κ (정답 대비)** | 채점자 답과 정답 최선 답(허용 답의 첫 값) 사이의 Cohen κ | 우연히 맞을 확률을 빼고 본 일치도. "결함"처럼 한 값이 대부분인 칸에서 일치율이 부풀려지는 것을 걸러 낸다 |
| **κ (채점자끼리)** | 채점자 1과 채점자 2 답 사이의 Cohen κ (참고 지표) | 정답 라벨과 무관하게, 기준서만 보고 두 사람이 같은 판정을 내리는가 |
| **Critical 인식률** | Critical 측정 20건 중 채점자가 우선순위 Critical 또는 처리 긴급 사인 요청으로 둔 비율 | 가장 비싼 실수를 재는 라벨에 사람도 동의하는가 |

모듈은 모듈1(필수)과 모듈2(선택)를 " / "로 합쳐 모델 응답과 같은 규칙으로 채점한다(고른 모듈이 모두 허용 답 안에 있어야 일치). κ는 모듈1과 정답 최선 모듈로 계산한다. 채점자가 고른 확신도와 메모는 지표에 넣지 않고 불일치 검토의 자료로 쓴다.

## 4. 판단 기준 (사전 등록)

| 칸 | 허용 답 일치율 | κ (정답 대비) | 이유 |
| :--- | :---: | :---: | :--- |
| 처리 · 분류 · 우선순위 | 85% 이상 | 0.61 이상 | 회귀 게이트가 하락을 0~2응답으로 엄하게 보는 칸이라 라벨도 엄하게 본다. 0.61은 Landis·Koch(1977) 구간에서 "상당한 일치"가 시작되는 값이다 |
| 모듈 · 재현 정보 · 발생 빈도 | 75% 이상 | — | 틀려도 뒤 단계(재배정·재현)에서 바로잡을 수 있는 칸이다. 게이트 허용폭과 같은 논리다 |
| Critical 측정 20건 | 인식률 90% 이상 | — | 미달이면 "이 문항의 정답은 Critical"이라는 전제부터 다시 본다 |

- **두 채점자 모두** 기준을 넘어야 그 칸의 라벨을 "신뢰"로 판정한다. 한 명이라도 못 넘으면 그 칸의 불일치 문항을 검토한다.
- 기준은 이 문서를 커밋한 뒤 바꾸지 않는다. 결과를 보기 전에 선택 규칙을 고정한다는 원칙([ML 08/18][ml0818])이며, QA 실무로 보면 판정 기준 합의를 테스트 전에 마치는 것과 같다.

## 5. 결과에 따른 처리 (사전 등록)

| 결과 | 처리 |
| :--- | :--- |
| 칸이 기준을 넘음 | 라벨을 그대로 쓴다. v1.4까지의 정답률과 게이트 판정을 그대로 인정한다 |
| 칸이 기준에 못 미침 | 불일치 문항(채점자 중 한 명이라도 허용 답 밖)을 모아 아래 절차로 검토한다 |
| Critical 인식률 미달 | 채점자가 Critical로 보지 않은 문항을 같은 절차로 검토한다 |
| 두 채점자끼리도 갈린 문항 | 기준서 경계 규칙(P-B1~B6)에 없는 새 경계 사례 후보로 기록한다. v1.5 라우팅의 "사람 검토" 근거 자료로 쓴다 |

**불일치 검토 절차**

1. 문항마다 정답 라벨, 두 채점자의 답·확신도·메모, 관련 기준서 조항을 한 표에 모은다. **모델 응답은 보지 않는다.** 보면 "모델이 맞히는 쪽"으로 라벨을 고치게 되기 때문이다.
2. 검토자가 문항마다 넷 중 하나로 판정한다: ① 라벨 유지(채점자의 적용 실수) ② 채점자의 답을 허용 답에 추가(원래 갈리는 판단) ③ 라벨 변경(기존 라벨의 오류) ④ 기준서 문구 보완(규칙이 모호함).
3. 판정과 이유를 [`docs/dataset/review_log.md`](../docs/dataset/review_log.md)에 기록한다.
4. 라벨이나 기준서가 바뀌면 v1.5 평가셋으로 새로 만들고(v1.4 파일은 그대로 둔다), 게이트 기준선과 이후 측정을 바뀐 라벨로 다시 채점한다. 저장된 실행 기록으로 다시 채점하므로 모델을 다시 돌리지 않는다.

## 6. 한계

- **채점자가 2명이다.** κ는 표본이 작으면 오차가 크다. 수치 자체보다 **어느 문항에서 갈렸는가**를 주로 본다.
- **경계 규칙의 판정이 기준서에 들어 있다.** 기준서는 부서마다 갈리는 6가지 상황(P-B1~B6)에 검토자의 판정을 적어 두었고, 안내서도 그대로 옮겼다. 따라서 경계 문항의 일치율은 "원래 판단이 갈리는가"가 아니라 "그 규칙에 해당하는 상황임을 알아보는가"를 잰다.
- **저장소가 공개되어 있다.** 채점자는 저장소를 보지 않기로 안내받지만 기술적으로 막을 수는 없다. 판정 시트의 문항 번호를 섞은 것은 이 위험을 줄이기 위해서다.
- **모델은 실행하지 않는다.** 이 단계는 라벨만 잰다.
